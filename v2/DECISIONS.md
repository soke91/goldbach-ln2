# DECISIONS

되돌릴 때 필요한 것만. 결과는 여기 쓰지 않는다.

형식: 한 항목 3줄 이내 — 무엇을, 왜, 무엇이면 뒤집는가.

---

**데맨드 사이드 진술의 집은 `paper/theorem_A.md` 하나.**
`wall_v3.md`가 같은 일곱 라벨을 다시 진술하고 있었다 — 증명은 한쪽에만
있으므로 진술도 한쪽에만 둔다. 뒤집는 조건: 두 문서를 합칠 때.

**스크립트 이름은 README §4 접두사를 따른다.**
논문이 부르던 옛 이름(`thmA_*`, `circle_margin` 등)은 새로 쓸 때 개명하고
논문의 인용도 같이 고친다. 뒤집는 조건: 접두사 규약을 버릴 때.

**G9(홀CR)와 G10(부른 스크립트 실재)을 게이트에 넣었다.**
둘 다 침묵하는 고장이었다 — 줄 번호가 어긋나도, 재현 불가능한 표가 남아도
아무것도 울지 않았다. 뒤집는 조건: 변환기를 버리고 마크다운을 손으로 쓸 때.

**M9 를 린트로 바꿨다 (G77), 유예 명단 스물과 함께.**
README 규칙이 같은 오류를 세 번 못 막았다 — rem:thetalaw U4, rem:alphalocal
Z4, rem:deficitshape B5. 검사 이전 스크립트 스물은 G16·G17 처럼 명단에 두어
재계산 없이 새 작업에만 물린다. 뒤집는 조건: 명단이 빌 때, 또는 방아쇠가
오탐을 내기 시작할 때.

**증거 경로가 `verify/` 도 가리킬 수 있게 했다 (G1·G70·G11).**
pass2 가 처음으로 재검증 스크립트로 논문 remark 를 떠받쳤는데, G1·G70 은
`code/` 밑만 찾고 G11 은 `results/` 밑만 훑어서 **실재하는 증거를 없다고
보고했다.** 규칙("인용된 증거는 실재해야 한다", "인쇄된 소수는 결과 파일에서
와야 한다")은 그대로이고 닿는 범위만 넓혔다 — 재검증 트리의 결과는
`verify/passN/results/` 에 있고 그것도 결과 파일이다. 게이트를 통과시키려고
규칙을 무르게 한 것과 이것을 구별하는 기준: 넓힌 뒤에도 같은 위반이
잡히는가. 잡힌다. 뒤집는 조건: 재검증 트리를 논문 증거로 쓰지 않기로 할 때.

**G4 도 `verify/` 를 본다 — 그리고 내 출력이 걸렸다.**
지난 결정이 G1·G70·G11 만 넓히고 G4 를 놓쳤다. G4 는 결과 경로를
`results/` 밑에서만 찾고 없으면 **조용히 넘어가는** 분기라, pass2 의 결과
파일 셋이 `STATISTIC:`·`FIELD:` 없이 통과하고 있었다. v1 스탬프에서
기록하던 결함(마당 없이 인쇄된 수)이 그것을 기록하는 내 출력에 있었다.
넓히고, 다섯 스크립트의 머리글을 고치고, 게이트 탈출 경로가 머리글 없이
쓰던 것도 고쳤다 — 예측이 깨진 실행에서만 마당 없는 결과가 남는 구조였다.
뒤집는 조건: 없음. 이건 규칙 확장이 아니라 누락 복구다.

**G78 을 넣었다 (상수는 자기 결과 파일에 닿아야 한다), 명단 스물넷과 함께.**
G4 는 `STATISTIC:`·`FIELD:` 줄의 **존재**만 본다. 이름 없이 마당을 부르는
`FIELD:` 는 아무것도 고정하지 않고, 그건 verify/pass2·pass3 가 다른 트리의
스탬프 둘에서 찾아낸 바로 그 결함이다. 재어 보니 154 짝 중 22 에 구멍이
있었고 그중 일곱이 `SEED` — 씨앗이 안 적힌 널은 그것을 보고하는 파일만으로
재현되지 않는다. 기존 것들은 명단에 두고 **명단은 줄기만 한다**. 빚을 문서가
아니라 게이트에 둔다. 뒤집는 조건: 결과 파일이 홀로 서야 한다는 G4 의
전제를 버릴 때.

**G78 명단을 스물넷에서 열아홉으로 줄였다 — 그리고 둘은 값 때문에 남긴다.**
씨앗 일곱 중 다섯을 닫았다. 나머지 둘(`audit_residue_arithmetic`,
`lab_primorial_ladder`)은 사다리 상류라, 헤더 한 줄을 고치면 G18 이
재실행을, G22 가 소비자 전부의 재실행을 요구해 `N ≤ 1.97e9` 의 사다리
재계산까지 번진다 — 몇 시간이고 수는 똑같이 돌아온다. 값을 인정하고
명단에 둔다. 뒤집는 조건: 사다리를 다른 이유로 다시 돌릴 때 같이 갚는다.

**수정시각은 git 이 안 나른다는 것을 적어 둔다.**
G18·G22 는 mtime 을 비교한다. 이번 틱에 불필요한 재실행으로 순서를 망가뜨린
뒤, 내용이 HEAD 와 동일함을 확인하고 게이트를 신탁 삼아 시각만 앞으로 고정점
수리했다(열두 바퀴). 그렇게 복구된다는 것 자체가, **게이트 통과라는 성질이
저장소가 아니라 작업 사본에 있다**는 뜻이다. 스탬프 둘에서 기록한 것과 같은
부류의 결함이 한 층 위에 있고, 여기서는 안 고쳤다. 뒤집는 조건: 결과 파일이
자기가 읽은 입력의 해시를 적게 할 때 — 그러면 mtime 이 필요 없어진다.
